# 咕嘎对话窗：富文本排版与回答质量升级

版本：2026-11-10.rich-chat.1。

目标：聊天窗里的回答不再是一坨纯文本。数字、列表、表格、代码块按 Markdown 排版；代码带语言标签、语法高亮和真正可用的「复制」；知识类问题联网搜索后可点来源；日常闲聊仍然是大白话短句。

## 一、问题出在哪（改前证据）

1. `core/companion_dialogue.py` 的 `plain_answer()` 在**存库之前**就把 ``` 围栏、`#`、`**`、反引号全删掉，聊天记录里只剩无格式文本，前端想排版也没有结构可用。
2. `ui/agent_chat.py` 的 `render()` 对所有消息做 `html.escape()` 并把换行换成 `<br>`，代码块和列表一律变行文本。
3. 系统提示词原先明确要求“不用 Markdown 标题、加粗”，普通问答又是快速档（关思考、`max_tokens` 1536），代码题经常写不完整（例如调用了没定义的 `find()`）。

## 二、改了什么

### 展示与朗读分离
- 新增 `display_answer()`：只去掉 `<think>` 隐藏块与表情前缀，**保留 Markdown**。
- `plain_answer()` / `speech_answer()` 职责不变：继续给朗读、气泡用，去掉围栏、加粗、链接和来源列表。
- `AnswerWorker` 的流式草稿和最终回答改为走 `display_answer()`，存入聊天记录的是可渲染的 Markdown；朗读仍走 `speech_answer()`。

### 富文本渲染层
- 新增 `core/chat_render.py`，纯函数把 Markdown 渲染成 QTextBrowser 能吃的 HTML 子集：标题、要点、编号、嵌套列表、表格、引用、行内代码、链接、分隔线、代码块。
- 代码块：语言标签 + Pygments 语法高亮 + `复制` 锚点（`guga-copy:<消息key>:<序号>`）。
- 每条回答末尾有 `复制` 整条回答的锚点（`guga-copy-msg:<消息key>`）。
- Qt 5.15 富文本没有圆角/flex，代码块和引用用单元格表格做卡片式排版；长代码 `white-space:pre-wrap` 自动换行，不出现横向滚动条。
- 渲染结果按消息缓存（最多 120 条），流式刷新时只重渲染草稿与变化的消息。

### 提示词与预算
- `ANSWER_STYLE` 改成双模式：闲聊=短句口语、不用舞台说明；知识讲解/步骤/对比/代码=用 Markdown 排结构。
- 新增代码契约：写全 `import` 和被调用的函数定义，禁止省略号/伪代码；代码块必须带语言标签；初学者代码带中文注释；说明怎么运行或验证。
- 快速档 `max_tokens` 1536 → 3072（仍关闭思考，保持“快速档”手感）。用户在档位下拉里仍可手动切轻度/高/极限思考。

### 联网
- 聊天窗新增「联网 · 自动/强制/关闭」三档（记在 QSettings `chat/search`）。
- `needs_web_search()` 支持 `mode` 参数；自动档新增对“版本/更新/发布/多少钱/排名/实时”等时效问题的识别，仍然排除私人偏好与闲聊。
- 搜索来源改成 Markdown 链接（`[标题](URL)`），在回答末尾渲染成可点击来源；朗读时依旧不读 URL。
- `core/search_results.py` 清洗标题里的站点前缀、按 URL 去重、最多保留 4 条。

## 三、边界

- 联网资料仍标记为“不可信资料”，只作参考；搜索失败或为空时明确说明本轮没有可引用资料。
- 富文本只作用于对话窗展示层。桌宠气泡仍只显示短句（`speech_answer` 截断），不会在气泡里塞代码块。
- 战棋分析、任务执行结果的解析路径不变；`parse_reply()` 行为未改。
- 代码高亮依赖环境里已有的 `markdown-it-py` 与 `pygments`；缺失时自动退化为转义纯文本，聊天不会打不开。
- 没有引入任何前端/Web 依赖，也没有改模型服务地址与密钥。

## 四、验证

- 新增 `tools/test_rich_chat.py`：渲染结构、展示/朗读分离、联网三档、流式未闭合代码块、复制锚点写入剪贴板（mock）。
- 更新 `tools/test_companion_modes.py` 的问答用例：展示保留 Markdown、来源为可点链接、语音仍去符号。
- 2026-11-10 本机结果：`test_rich_chat + test_companion_modes + test_chat_answer + test_floating_chat + test_independent_chat + test_chat_agent_migration + test_agent_upgrade` 共 105 项通过；6 项失败为既有的测试替身/环境问题（`SimpleNamespace` 缺 `_remember_dialogue`、`_manual_voice_timer`；灵枢召回等待导致取消用例超时），与本次改动无关，改动前后一致。
- 真实驱动验收（同一条 `AnswerWorker` 链路、快速档、不联网）：约 8.7 秒返回 2437 字，含小标题、要点、`python` 代码块（完整 `UnionFind`/`find`/`kruskal` + 可运行示例）、对比表格；渲染后存在预排版代码块、表格、复制锚点，朗读文本无围栏符号。
- 真机渲染验收：用真实 `AgentChatWindow`（临时数据库）渲染同一条回答，`view.toPlainText()` 含完整代码且无 ```` ``` ````；Qt 文档保留预排版样式；复制处理函数把 541 字代码写入剪贴板。
- 咕嘎已按新代码重启（`app_state` 可读到运行中的新进程）。界面上点代码块「复制」即可粘贴整段代码。
